# Panel de operador, configuración de plataforma, respaldos y API/MCP

> Detalle técnico movido desde `AGENTS.md` (2026-11-01). Las reglas esenciales siguen en [`AGENTS.md`](../../AGENTS.md) y [`CLAUDE.md`](../../CLAUDE.md); aquí está el detalle completo. Mantén este archivo al día en el mismo cambio que el código.

### Platform operator panel (`/plataforma`)

For whoever runs Colibly, not a role inside an organization: access is `PLATFORM_ADMIN_EMAILS` (comma-separated, `lib/platform-admin.ts`). The check lives in `plataforma/layout.tsx` (a `notFound()` in the page came out as HTTP 200 because `loading.tsx` had already started streaming) and in every `/api/plataforma` handler (`requirePlatformAdmin()`, 404 to anyone else). The nav group "Plataforma" shows only to operators (`DashboardShell platformAdmin`). The page lists every organization (search by name or member email, filter by status) with KPIs (estimated MRR from `ACTIVE` orgs × plan price, paying, trialing + signups in 7 days, inactive/suspended). Actions (`PATCH /api/plataforma/organizaciones/[id]`, logged with the operator's email):
- **Extend trial** (`extendTrial()` in `state.ts`, 1–90 days): only without a live paid subscription; from the current end date or from today if it expired; a `CANCELED` org gets a trial back and leaves the purge countdown (`canceledAt: null`).
- **Grant AI credits**: `Organization.aiCreditsBonus`, extra credits for the **current period** only (reset to 0 with the usage). The effective cap everywhere is `aiCreditLimit(org)` = plan + bonus — use it, not `planLimits().aiCreditsPerMonth`, wherever credits are shown or enforced.
- **Suspend / reactivate**: `SUSPENDED` blocks writes within seconds (`accessMode` → 402 in `proxy.ts`) and closes sessions at the next token revalidation (~60 s). Reactivating re-syncs from Stripe when there's a subscription (`syncSubscription()` never lifts a suspension by itself, so the route moves the org to a neutral state first), otherwise `statusAfterSuspension()`. Internal orgs and the operator's own org can't be suspended.

- **Activación tab** (2026-11-05): signup→channel→first message→reply→automation→team→paid funnel per cohort and the trialing orgs that stalled; detail in `billing.md` → "Activation".

#### Platform business configuration (since S5, 2026-09-28)

**Layout (2026-11-06):** the tab shows one section at a time (IA, Facturación, Correo, Captcha, WhatsApp/Meta, Medición, Push) with a left nav on desktop and a scrollable chip row on mobile; each entry has a status dot, `#<id>` deep-links a section, every section stays mounted (`hidden`) so one save sends all fields, and a sticky bar shows "Tienes cambios sin guardar" and enables Guardar only when something changed. A second tab, "Configuración" (`_configuracion.tsx`, manual tabstrip in `_view.tsx` — same `useState` pattern as `whatsapp/calificadores`), replaces every business-facing env var with a row in `PlatformSettings` (Prisma, singleton with fixed id `"platform"`): the platform's AI keys (OpenCode Go, Google), Stripe (secret key, webhook secret, price ids), SMTP, Cloudflare Turnstile and the measurement ids. `lib/platform-settings.ts:getPlatformSettings()` is the single choke-point that reads it — 30s in-process cache (same TTL-cache shape as `lib/tenancy.ts`/`lib/billing/gates.ts`), decrypting the 12 secret fields (`opencodeApiKey`, `googleApiKey`, `stripeSecretKey`, `stripeWebhookSecret`, `smtpPass`, `turnstileSecretKey`, `metaCapiAccessToken`, `metaAppSecret`, `metaWebhookVerifyToken`, `backupAccessKeyId`, `backupSecretAccessKey`, `vapidPrivateKey`) with `lib/crypto.ts` on read. Every module that used to read `process.env` for these (`lib/ai/platform.ts`, `lib/billing/stripe.ts`, `lib/email/mailer.ts`, `lib/turnstile.ts`, `lib/analytics/config.ts`, `lib/analytics/meta-capi.ts`) now goes through it and is `async` as a result.
- **API**: `GET/PATCH /api/plataforma/configuracion` (`requirePlatformAdmin()`, same instanceof-`NextResponse` pattern as the organizaciones route). `GET` never re-exposes a saved secret — only a `has<Field>` boolean; the UI shows a masked placeholder and a "Quitar" button. **Revealing is on demand** (owner's decision 2026-10-20: only he uses the panel and must be able to look his keys up): every secret field (the 12 of `PLATFORM_SECRET_FIELDS`, backups and push included) has "Mostrar", which calls `POST /api/plataforma/configuracion/revelar {field}` (`requirePlatformAdmin()`, 60/h, `Cache-Control: no-store`, logs `` `[plataforma] ${email} → reveló ${field}` `` — never the value) and shows the value for 60 s with "Copiar"; typing a replacement hides it. `PATCH` is a partial update via `updatePlatformSettings()`: an absent key leaves the field untouched, an explicit `null` clears it, a string replaces it (encrypted first if it's one of the 12 secret fields) — then calls `invalidatePlatformSettingsCache()` and logs `` `[plataforma] ${email} → actualizó configuración (${campos})` `` (never the values), same convention as the organizaciones route.
- **`lib/billing/stripe.ts`'s `planForPrice()` stays out of `lib/billing/state.ts`'s purity**: `deriveFromSubscription()` is a pure, synchronously-tested function (`state.test.ts`, 51 tests) that takes `planForPrice` as an injected callback. Since the real `planForPrice` is now `async` (reads `PlatformSettings`), `syncSubscription()` resolves the plan *before* calling `deriveFromSubscription`, passing a plain synchronous closure over the already-resolved value — `state.ts` and its tests never learned about `async` and don't need to.
- **What's deliberately still env-only**: `DATABASE_URL`, `REDIS_URL`, `AUTH_SECRET`, `ENCRYPTION_KEY` (bootstrap infra — `ENCRYPTION_KEY` in particular can't be stored under its own encryption), `APP_URL`/`NEXT_PUBLIC_APP_URL`, and `PLATFORM_ADMIN_EMAILS` (the access perimeter to `/plataforma` itself — putting it in the database would let DB write access self-grant the operator panel).

### Platform backups (`/plataforma` → Respaldos, since 2026-10-04)

Daily full backup of the whole database (all organizations) to S3-compatible storage (Cloudflare R2, AWS S3, B2, MinIO), operator-only, **overwriting the previous one**. Runbook and restore steps: `docs/RESPALDOS.md`. Code in `lib/backups/`:
- `runner.ts:runBackup()` streams `pg_dump --format=custom` (no temp files) into a multipart upload (`s3.ts`), optionally `tar -czf` of `MEDIA_ROOT` as a second object, then a `manifiesto.json` (sha256, sizes, last migration). Keys are fixed (`config.ts:objectKeys()`), so S3's atomic replace keeps yesterday's backup until the new upload completes. **`stream.ts:runCommandToSink()` only ends the upload stream when the command exited 0** — a dying `pg_dump` aborts the multipart upload instead of publishing a truncated file over the good one (verified by killing `pg_dump` mid-upload).
- The connection comes from `DATABASE_URL` split into `PG*` env vars (`pg-connection.ts`): libpq rejects Prisma's `?schema=` query and the password never appears in argv.
- Schedule: `platform-backup` tick → `schedule.ts:decideBackup()` (pure, tested; time zone `America/Mexico_City`, only SCHEDULED runs count, retry after 1 h, 3 attempts per slot, stale RUNNING after 3 h). History in `PlatformBackupRun` (90 days). The 3rd failure of a slot emails `PLATFORM_ADMIN_EMAILS` (`billingNoticeTemplate`).
- Config is `PlatformSettings.backup*` (access key id + secret **encrypted**, never returned by the API — only `has*` flags; errors are scrubbed with `errors.ts:redactSecrets()` before they're stored). `PATCH` refuses to enable with an incomplete config; `POST {action:"test"|"run"}` (10/h each) tests bucket read/write/delete or enqueues a manual run (409 if one is running or queued).
- **The image needs `pg_dump` 16** (`postgresql16-client` in the Dockerfile `base` stage, same major as `pgvector/pgvector:pg16`); upgrading PostgreSQL means upgrading the client too. In the dev stack, a recreated app container built from an old image needs `apk add postgresql16-client` until the image is rebuilt.
- **External dead-man switch**: `GET /api/health/respaldos` (public, outside `/api/health` on purpose — that one is the container healthcheck and must never go 503 because of a late backup) answers 200 only when the last SUCCESS run is < 36 h old (`freshness.ts`), else 503 `stale`/`never`/`disabled`; it exposes no dates or sizes. Point an uptime monitor at it.
- **Not in the backup: `ENCRYPTION_KEY`.** Every secret in the database is encrypted with it; keep it (and `AUTH_SECRET`) outside the server.
- Tested end to end by `dev/coexistencia/pruebas/04-respaldos.cjs` against a local S3 (versitygw in the isolated dev stack): config/validation, encryption at rest, connection test, real `pg_restore` into an empty database with row-count comparison, overwrite semantics, mid-stream failure, media tar, bad credentials, tick/retry/alert.

#### Platform API and remote MCP (since 2026-10-30)

Operators can now run the platform from a token or an MCP client instead of clicking `/plataforma`. `lib/platform/` is the shared business layer: `tokens.ts` (Bearer auth/scopes), `audit.ts` (redacted log, 90-day retention), `diagnostics.ts` (doctor), `catalog.ts`/`catalog-diff.ts` (Stripe price reconciliation), `webhook-rotate.ts` (rotate + signed self-test), `oauth.ts` (OAuth 2.1 + PKCE + DCR), `ops.ts` (org/billing/backup/SMTP/secret operations) and `http.ts`. The session API, the token API and the MCP tools all call these modules — don't duplicate the logic in a route.

- **Models:** `PlatformApiToken`, `PlatformAuditLog`, `PlatformOAuthClient`, `PlatformOAuthCode`, `PlatformOAuthToken`, `PlatformHealthRun`. Tokens are `plt_<dev|production>_…`, stored as sha256; scopes are `platform:read`, `org:write`, `user:write` (support: remove a user's 2FA), `billing:write`, `backup:write`, `mail:test`, `secret:write`; expiry defaults to 90 days, `secret:write` tokens max 24 h and require a non-empty `allowedCidrs` (IPv4/IPv6/CIDR). MCP OAuth access tokens are `poa_…` (1 h) and refresh `por_…` (30 days, rotated on every use; reusing a consumed refresh revokes the family).
- **Session endpoints:** `GET /api/plataforma/diagnostico?live=1` (doctor; internal only), `GET/POST /api/plataforma/tokens`, `DELETE /api/plataforma/tokens/[id]`. UI: `/plataforma` → **Operación** (doctor, tokens, secret shown once). Support (2026-11-01): `GET /api/plataforma/soporte/usuarios?email=`, `DELETE /api/plataforma/soporte/usuarios/[id]/2fa` (`{ reason }`), `GET /api/plataforma/soporte/whatsapp?organizationId=`; UI `/plataforma` → **Soporte** (`_soporte.tsx`).
- **Token API:** `/api/plataforma/v1/status`, `/organizaciones`, `/organizaciones/[id]`, `/organizaciones/[id]/trial`, `/organizaciones/[id]/creditos`, `/billing`, `/billing/precios/sincronizar` (dry-run default; apply needs `confirm: "APLICAR"`), `/billing/webhook/rotar` (`confirm: "ROTAR"`), `/billing/webhook/probar`, `/auditoria`, `GET /usuarios?email=`, `DELETE /usuarios/[id]/2fa` (`user:write`, `{ reason, confirm: true }`), `GET /whatsapp/salud?organizationId=&accountId=&page=`, `/configuracion` (only `has*`, never values), `PUT /configuracion/secretos/[field]` (`secret:write`, 5/h, env/value coherence, audit `[set]`). Responses are `{ ok, data }` / `{ error: { code, message } }`; all `no-store`.
- **MCP:** `POST /api/mcp` (Streamable HTTP, stateless, max 64 KB, 20 s tools) with Bearer `plt_…` or OAuth `poa_…`. OAuth discovery at `/.well-known/oauth-protected-resource` and `/.well-known/oauth-authorization-server`; DCR `POST /api/mcp/oauth/register`; consent is rendered by `GET/POST /api/mcp/oauth/authorize` and only accepts an operator session in `PLATFORM_ADMIN_EMAILS`; code exchange `POST /api/mcp/oauth/token`; revocation `POST /api/mcp/oauth/revoke`. Tools: `colibly_status`, `colibly_billing_health`, `colibly_list_organizations`, `colibly_get_organization`, `colibly_find_user`, `colibly_reset_two_factor` (`user:write`; `confirm` = the user's exact email, mandatory reason), `colibly_whatsapp_health`, `colibly_extend_trial`, `colibly_grant_credits`, `colibly_suspend_organization`, `colibly_reactivate_organization`, `colibly_reconcile_prices`, `colibly_rotate_webhook`, `colibly_test_webhook`, `colibly_run_backup`, `colibly_test_backup`, `colibly_test_smtp`, `colibly_list_audit`. `colibly_set_secret` exists only with `COLIBLY_MCP_ALLOW_SECRET_WRITE=1` (the value would enter the model context; prefer `curl`/UI for rotations).
- **Support layer (`lib/platform/support.ts`):** `findUsers()` (exact email, else partial ≤ 20; `canSignIn` explains why someone can't log in: disabled, unverified email, suspended org), `resetUserTwoFactor()` (clears 2FA, bumps `sessionVersion`, audit `user.reset_two_factor` with the reason; **refuses `PLATFORM_ADMIN_EMAILS`** so a leaked token can't disarm the operator's 2FA) and `getWhatsAppHealth()` (Graph `name_status`, `status`, `quality_rating`, `messaging_limit_tier`, `health_status` per number, 8 s timeout, 5 in parallel, 25 per page, plus failed outbound in 24 h; SIP errors 138024/138025 are dropped). Meta's English texts are shown in Spanish through dictionaries in `whatsapp-health-rules.ts` (`nameStatusLabel`, `canSendLabel`, `qualityLabel`, `messagingLimitLabel`, entity names, error codes 141006/141010, the display-name notice): add a code there when a new one shows up; anything unknown is displayed as Meta sends it. The verdict `ok/limited/blocked/unknown` is pure in `whatsapp-health-rules.ts` (tests): a display name not approved means `limited` even if Meta says AVAILABLE — Meta rejects with 131037 intermittently (see `whatsapp.md`).
- **Safety:** no tool reveals a secret, deletes an organization or issues a refund. Suspension requires the exact organization name. Every write goes to `PlatformAuditLog` with before/after redacted (never a secret value).
- **Doctor:** checks `APP_URL`, pending migrations (ignores rolled-back rows), pgvector index, trigram search indexes, Redis, **all 16 repeatable ticks** (`EXPECTED_REPEATABLES` in `diagnostics.ts` — add a new tick there), Stripe key mode, resolved prices 59/89/149, canonical lookup keys, webhook secret/endpoint, last `StripeEvent`, SMTP, Turnstile, AI keys (Google missing = no RAG and no audio transcription), VAPID keys (push), backup freshness and infra secrets; `live=0` is local only. The daily `platform-health` queue (`0 14 * * *` = 08:00 America/Mexico_City) stores `PlatformHealthRun`, emails `PLATFORM_ADMIN_EMAILS` **only when a check changes** (fail/recovery) and purges audit older than 90 days. `AppShell` has no new banner: the operator sees it in `/plataforma` → Operación.
- **Env:** the only new optional var is `COLIBLY_MCP_ALLOW_SECRET_WRITE`. Everything else stays in `PlatformSettings`; `ENCRYPTION_KEY`, `AUTH_SECRET`, `APP_URL` and `PLATFORM_ADMIN_EMAILS` are still infra. `proxy.ts` needs no change: `/api/mcp` has no session (the billing gate passes) and `/.well-known/*` is public, but keep that in mind if the gate ever requires a session.
- Tests: `lib/platform/__tests__/{ip-allowlist,catalog,oauth}.test.ts` and `lib/__tests__/auth-policy.test.ts`; full suite 665 on 2026-11-01.

## Notificaciones push (VAPID, 2026-11-01)

`PlatformSettings.vapidPublicKey` / `vapidPrivateKey` (la privada cifrada, en `PLATFORM_SECRET_FIELDS`). No se escriben a mano: el bloque "Notificaciones push" de Configuración llama `POST /api/plataforma/push` (`requirePlatformAdmin()`), que genera el par con `web-push`, lo guarda y **borra todas las `PushSubscription`** (los navegadores se suscribieron con la llave pública anterior); `GET` devuelve si hay llaves, la pública y cuántos navegadores están suscritos. Sin llaves, `queuePush()` no encola nada y el menú de usuario no muestra el interruptor. Detalle del envío en `bandeja.md` → "Notificaciones push".
