## Brand and public site (since 2026-09-25; renamed to Colibly 2026-09-27)

The product is **Colibly** (domain `colibly.com`). History: SundayCRM → SunflowCRM (sundaycrm.com belonged to someone else) → Colibly (2026-09-27, see `docs/PLAN_LANZAMIENTO.md`). The name and domain live in `lib/brand.ts` (`BRAND_NAME`, `BRAND_TAGLINE`, `BRAND_DOMAIN`, `BRAND_CONTACT_EMAIL`) — use them in new user-facing text instead of a literal; the public URL of the app still comes from `APP_URL` at runtime (`lib/app-url.ts`), so dev keeps pointing at localhost. Everything is named Colibly since 2026-09-27: GitHub repo `ludaisca/Colibly`, folder `/data/Proyectos/Colibly`, npm package, compose project `colibly` (pinned with `name:` in the override), database `colibly_db`. Only history keeps the old names (applied migrations, `prisma/baseline/`, audits) plus the seed users `@sundaycrm.test` in the dev database; the webchat widget reads its old `localStorage` key `sundaycrm_webchat_token_*` once and migrates it to `colibly_webchat_token_*`. Webhook headers are `X-Colibly-Signature` / `X-Colibly-Event` / `X-Colibly-Delivery` (automation webhook steps send `X-Colibly-Automation`), User-Agent `Colibly-Webhooks/1.0`; the data export format is `colibly-export-v1`.
- **Logo (Nexo, 2026-10-25)**: geometric C + east-pointing triangle on the Laguna accent — `BrandMark` in `app/components/ui/logo.tsx` (token colors, used by `Logo` and the app shell) and the same shape in fixed colors in `lib/brand-mark.ts` (`app/icon.svg`, `app/apple-icon.tsx`, the share image). Masters/variants in `tmp/logo-design/kit/`.

- **Public site** is the `(marketing)` route group: `/` (landing), `/precios`, `/contacto`, `/eliminar-datos` (public deletion instructions — the URL to register in Meta; the status page `/eliminacion-de-datos/[code]` is separate), `/terminos`, `/privacidad`. None of them are in `proxy.ts` lists, but the app host redirects them to the site host. Registration is OPEN (decision 2026-10-18): CTAs point to `/register`, prices come only from `lib/billing/plans.ts`; the beta application form is just an optional contact. A new user gets a welcome email (`welcomeTemplate`) when the email is first verified. `app/not-found.tsx`, `error.tsx` and `global-error.tsx` are the Spanish 404/500 screens. **The landing never calls `auth()`**: `proxy.ts` redirects a signed-in user from `/` to their panel (`/whatsapp/chat` for ejecutivo, `/dashboard` otherwise). Below `md` the header shows a hamburger menu (`app/components/ui/site-mobile-nav.tsx`, shared with the beta layout) instead of the section links; the main call to action is the `CTA` constant in `page.tsx` — reuse it so every button says the same thing.
- **Measurement** (`lib/analytics/`, `app/components/analytics/analytics.tsx`): Meta Pixel, GA4 and Google Ads load **only after the visitor accepts the cookie notice** (choice in `localStorage` `colibly_consent`; "Preferencias de cookies" in the footer resets it) and only when their ids exist in `PlatformSettings` (`metaPixelId`, `gaMeasurementId`, `googleAdsId` + `googleAdsSignupLabel` — configured from `/plataforma`, validated formats, `lib/analytics/config.ts:getAnalyticsConfig()`) — without them there's no banner and no third-party script. Mounted in the `(marketing)` and `(auth)` layouts (registration is the conversion), never in the panel. Events: elements with `data-track="cta"` + `data-track-location` (clicks), `#precios` in view, `<details data-track="faq">` opened, and `sign_up` after registration. The register page sends the same event id in `x-analytics-event-id` (only with consent) so `POST /api/auth/register` reports `CompleteRegistration` through Meta's Conversions API (`meta-capi.ts`, needs `metaCapiAccessToken` in `PlatformSettings`) and Meta deduplicates it with the Pixel's. This is Colibly's own ad measurement — unrelated to `lib/meta/conversions.ts` (customers' ad accounts).
- **CSP** (`next.config.ts`): global and strict (`'self'`), with the third-party origins the public site needs listed explicitly (Meta, Google Analytics/Ads, Cloudflare Turnstile). Until 2026-09-27 it only allowed `'self'`, so the browser blocked the Pixel/gtag scripts and beacons even with the ids configured. A new third-party script or beacon needs its origin added there — verify in the browser (`securitypolicyviolation`), `tsc` won't tell you.
- **Signup captcha** (`lib/turnstile.ts`, `app/components/ui/turnstile.tsx`, shared action in `lib/turnstile-shared.ts`): Cloudflare Turnstile, optional — required on `/register` only when both keys are configured in `PlatformSettings` (`turnstileSiteKey`/`turnstileSecretKey`, from `/plataforma`; `register/page.tsx` is an async server wrapper that awaits the site key and passes it to `_form.tsx`). `POST /api/auth/register` verifies the token before touching the DB, and `lib/turnstile.ts` requires `success === true`, the stable action `signup` (the widget sends it and siteverify returns it) and the frontend hostname: production accepts only the `APP_URL` host and fails closed without it, development also accepts `localhost`, `127.0.0.1` and single-label Tailscale names. A rejected/missing token is 400, but if Cloudflare itself can't be reached it lets the signup through (logged) — the per-IP limits still apply. `remoteip` goes along when known. Cloudflare's test keys (site `1x00000000000000000000AA`, secret `1x0000000000000000000000000000000AA` always passes / `2x0000000000000000000000000000000AA` always fails) are handy for local testing, pasted into `/plataforma`.
- **Landing chat**: `LANDING_WEBCHAT_ACCOUNT_ID` = a WEBCHAT account of Colibly's own organization (its allowed origins must include the public domain); the `(marketing)` layout loads its `widget.js`. Leads who write there land in that organization's inbox.
- **SEO and sharing**: `metadataBase` comes from `APP_URL` in the root layout's `generateMetadata()` (with `connection()`, because the domain only exists at runtime), so canonical, Open Graph and the file-based images resolve to the real domain. Files: `app/icon.svg` (favicon), `app/apple-icon.tsx`, `(marketing)/opengraph-image.tsx` + `twitter-image.tsx` (both render `_share-image.tsx`, fixed palette colors), `app/robots.ts` and `app/sitemap.ts` (`force-dynamic` for the same reason). The landing emits JSON-LD (`SoftwareApplication` with the plans + `FAQPage`). **In dev, Next always points og:image to `localhost:PORT`** regardless of `metadataBase` (by design) — check share URLs on a production build. Prices and plan features come from `lib/billing/plans.ts` + `lib/billing/plan-features.ts` (shared with `/configuracion/plan`), so a limit change updates both.
- **Legal texts are drafts**: `app/(marketing)/_legal.tsx` holds the company placeholders (`LEGAL`) and the "borrador" notice; both pages mark open questions with `<Blank>`. They must be reviewed by a lawyer and the placeholders filled before public launch.
- **Onboarding checklist** on `/dashboard` (admins only, hidden once complete): `lib/onboarding.ts:getOnboardingSteps()` derives each step from real data (email verified, a channel, a bot or automation, a second member or invite, an ACTIVE plan) — there's no manual "mark as done".
